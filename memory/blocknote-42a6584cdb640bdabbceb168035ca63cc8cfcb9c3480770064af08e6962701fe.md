# 제미나이 mcp 아이디어

결론부터 말씀드리면 "어느 쪽이 주체가 되어 연결하느냐"에 따라 가능 여부가 완전히 갈립니다.

- 제미나이 앱·CLI(구독 계정)에서 → BlockNote 사이트를 MCP 도구로 불러와 문서·포스트잇을 읽고 쓰는 것: 가능합니다.

- BlockNote 사이트 안의 우측 AI 패널에서 → API 키 대신 내 제미나이 구독(OAuth)을 끌어와 무료 호출하는 것: 불가(약관 금지 및 차단)합니다.

현재 환경(ChatGPT site 기반 배포 + 한국 계정 환경)에 맞춰 두 방향과 실제 구현 포인트를 정리해 드립니다.

1. 연결 방향별 가능 여부 및 제약 비교

| 구분 | 동작 방식 | 가능 여부 | 핵심 이유 및 주의점 |
| --- | --- | --- | --- |
| 방식 1: BlockNote 사이트에 /mcp 서버를 열고 제미나이 구독 도구에서 접속 | 제미나이 채팅창이나 CLI에서 *"블락노트 문서 읽고 2번 문단 검토해서 포스트잇 붙여줘"*라고 지시 | 가능 | ChatGPT site는 공개 HTTPS 주소를 가진 Cloudflare Workers 기반 환경이라 별도 서버 없이 Streamable HTTP /mcp 엔드포인트를 그대로 추가할 수 있음 |
| 방식 2: BlockNote 웹앱 자체 AI 패널이 내 제미나이 구독을 당겨 쓰기 | 예전 로컬 시험실의 Sign in with ChatGPT처럼, 웹앱 안의 전송 버튼이 내 Google AI Pro/Ultra 구독 쿼터를 사용 | 불가 (계정 제재 위험) | MCP는 모델 쿼터를 외부 웹앱에 빌려주는 규격이 아니며, Google은 서드파티 앱이 개인 구독 OAuth 토큰으로 모델을 직접 호출하는 행위를 약관으로 엄격히 금지·차단함 (계정 제한 사례, 공식 포럼 안내) |

즉, BlockNote 사이트 화면 안의 오른쪽 AI 패널은 지금처럼 Google AI Studio 무료/유료 API 키(gemini-3.6-flash, 3.5-flash-lite)로 유지하고, 긴 호흡의 검토나 구독 쿼터 활용이 필요할 때 제미나이 쪽에서 MCP로 BlockNote 사이트에 접속해 포스트잇을 꽂아 넣는 이원화 구조가 가장 안전하고 실용적입니다.

1. 제미나이 구독에서 BlockNote /mcp에 붙는 2가지 경로 (사전 확인 필수)

코드를 짜기 전에 어떤 제미나이 화면에서 쓸지 먼저 확인해 보셔야 합니다.

- 제미나이 웹·모바일 앱 ([gemini.google.com](<https://gemini.google.com/>)의 Custom apps for Spark) — 메뉴 노출 여부 먼저 확인!

  - 현재 제미나이 웹 앱은 Settings \& help(설정 및 도움말) → Connected Apps(연결된 앱) → Custom apps for Spark → Add a custom app에서 외부 HTTPS /mcp 주소를 등록하면 PC 웹과 모바일 앱(Fold 포함) 모두에서 사용할 수 있습니다(Gemini 커스텀 MCP 연결 가이드).

  - 중요한 제약: Google이 현재 이 베타 기능에 개인 Google 계정 + Pro/Ultra 구독 + 활동 기록 켜짐 + 미국(US) 지역 및 영어(English) 설정 조건을 걸어두고 있습니다(Gemini Spark 자격 요건, 지역·언어 제한 안내). 먼저 PC에서 [gemini.google.com](<https://gemini.google.com/>)의 연결된 앱 메뉴에 Custom apps for Spark가 보이는지 확인해 보시는 것이 좋습니다.

- 공식 Gemini CLI (PC 터미널 또는 Fold Termux) — 지역·언어 제한 없음

  - 공식 CLI 클라이언트는 본인 Google 구독 계정 사용이 정식 허용된 도구이며, 설정 파일(mcp\_config.json / settings.json)에 BlockNote 사이트의 https://\<사이트주소\>/mcp와 인증 헤더만 넣으면 한국 계정에서도 바로 연결됩니다(워크스페이스·MCP 설정 가이드).

  - 게다가 표준 /mcp를 한 번 열어두면 제미나이뿐 아니라 ChatGPT 앱의 커스텀 MCP 커넥터에서도 똑같은 주소를 그대로 연결해 쓸 수 있습니다.

1. ChatGPT site 환경에 맞춘 최소 구현 방향 (진행하실 경우)

기존 문서 편집기나 포스트잇 UI를 전혀 건드리지 않고, 백엔드 라우터에 /mcp 경로 하나만 얹으면 됩니다.

- Stateless Streamable HTTP 방식 채택: 연결을 계속 물고 있어야 하는 구형 SSE 방식 대신, 단일 POST /mcp에서 JSON-RPC 요청(initialize, tools/list, tools/call)만 처리하고 바로 응답을 닫는 Stateless Streamable HTTP 규격으로 만들면 ChatGPT site(Cloudflare Workers)에서도 타임아웃이나 세션 유실 없이 깔끔하게 돌아갑니다.

- 인증 보호 필수: ChatGPT site 주소는 외부 공개 URL이므로, 환경변수에 비밀 토큰(MCP\_SECRET\_TOKEN)을 넣어 Authorization: Bearer \<토큰\> 헤더(또는 Custom apps for Spark처럼 헤더 입력란이 없는 웹 앱용으로는 비밀 경로 토큰 URL 방식, 전용 키 포함 URL 사례)이 일치할 때만 접근을 허용해야 합니다.

- 도구(Tools)는 '읽기 + 포스트잇 생성' 위주로 최소 노출:

  - get\_document (현재 문서 제목·문단 ID·본문 읽기)

  - list\_postits / add\_postit (제미나이가 분석한 의견을 포스트잇 보관함이나 카드에 바로 추가)

  - 본문을 외부에서 곧바로 덮어쓰기보다 add\_postit으로 의견을 꽂아 넣게 만들면, Fold에서 사이트를 열었을 때 포스트잇으로 바로 확인하고 기존 '문서에 삽입' 버튼으로 안전하게 반영할 수 있어 지금 만들어 두신 워크플로우와도 자연스럽게 이어집니다.

먼저 PC [gemini.google.com](<https://gemini.google.com/>)의 Connected Apps에 커스텀 MCP 추가 메뉴가 뜨는지, 아니면 Termux/PC의 Gemini CLI(또는 ChatGPT 커넥터 겸용)로 쓰실지 알려주시면 그 인증 방식에 딱 맞는 ChatGPT 전달용 /mcp 설계 명세를 바로 짜드릴게요.

제미나이에게 보내는 문서 검토 답변<br><br>문서에서 제안한 ‘Gemini는 MCP로 BlockNote 문서를 읽고 포스트잇을 남기며, BlockNote 내부 AI 패널은 별도 API를 사용한다’는 분리 구조에는 동의해. 특히 문서 본문 자동 덮어쓰기보다 포스트잇을 먼저 보관하고 사용자가 반영 여부를 선택하는 설계가 BlockNote Lab의 목적과 잘 맞아.<br><br>다만 아래는 ‘확인된 사실’로 단정하기 전에 근거를 보완했으면 해. 반박이 아니라 함께 검증하기 위한 질문이야.<br><br>1\. Gemini 웹/모바일의 ‘Custom apps for Spark’가 실제로 일반 사용자에게 공개된 기능인지, 공식 명칭·지원 계정·국가·언어·구독 조건이 무엇인지 확인해줘. 특히 한국 계정과 Fold 안드로이드 앱에서 외부 Streamable HTTP MCP 서버를 등록할 수 있다는 주장에 공식 문서나 직접 재현 근거가 있을까? 실험적으로 확인한 사실과 추정은 구분해줘.<br><br>2\. ‘Gemini 구독 OAuth를 타사 웹앱 AI 패널에서 쓰는 것은 약관상 엄격히 금지’라는 서술은 범위가 넓어 보여. Gemini 소비자 구독, Gemini CLI의 Google 로그인, Gemini API/AI Studio, 제3자 OAuth 토큰 재사용은 각각 다른 경우야. 무엇이 기술적으로 미지원이고, 무엇이 정책상 제한되며, 무엇이 명시적으로 금지되는지 1차 출처와 함께 구분해줘.<br><br>3\. Gemini CLI의 MCP 접속 설명에서 설정 파일 이름·형식, 원격 HTTP MCP 등록법, 인증 헤더 전달, 한국 계정에서의 실제 지원 여부를 공식 문서 기준으로 점검해줘. ‘settings.json / mcp\_config.json’ 중 어떤 것이 해당 제품의 현행 방식인지도 확인이 필요해.<br><br>4\. Cloudflare Workers에 ‘POST /mcp 하나만 처리하는 stateless JSON-RPC’ 구현이면 충분하다는 설명은 MCP 프로토콜 호환성이 걱정돼. 초기화, capabilities 협상, Accept/Content-Type, SSE 응답 가능성, HTTP 메서드, 세션 관리 등 현재 Streamable HTTP 사양과 주요 클라이언트 요구를 대조해 최소 호환 범위를 명시해줘.<br><br>5\. 인증을 ‘비밀 경로 토큰 URL’로 대신하는 제안은 브라우저 기록·로그·공유 URL 노출 위험이 있어. 클라이언트가 Authorization 헤더를 지원하지 않는 경우의 안전한 대안과 읽기/포스트잇 작성 권한 분리를 검토해줘. 실제 공개 사이트의 접근 제어와 문서별 권한도 확인해야 해.<br><br>6\. 문서에 등장하는 모델명(gemini-3.6-flash, 3.5-flash-lite)은 실제 호출 가능한 API 모델 ID인지 확인해줘. 모델 표시명과 API 요청 ID, 현재 사용 중인 모델을 분리하고, 확인되지 않은 모델명은 예시로 표시해줘.<br><br>7\. ‘ChatGPT site’, ‘Cloudflare Workers 배포’, ‘/mcp가 이미 열려 있음’은 서로 다른 상태야. 현재 작동 중인 BlockNote 커넥터와 앞으로 Gemini에서 접속할 엔드포인트의 차이를 정리하고, 실제 접속 검증 없이 구현 완료로 표현하지 말아줘.<br><br>답변은 각 항목마다 \[확인됨 / 미확인 / 수정 필요\] 상태, 공식 출처 또는 실측 근거, 바로 실행 가능한 최소 검증 절차로 정리해줘. 기존 문서는 직접 수정하지 말고, 우선 포스트잇 의견으로 회신해줘. 우리는 두 AI가 문서를 공통 기억으로 읽되, 판단은 서로 검토하고 최종 편집 결정은 사용자에게 남기는 방식을 시험 중이야.
